# 全量按钮布局与操作体验优化 PRD

> 版本：v1.1（全量布局方案 + 操作组件续修）
> 日期：2026-10-15
> 状态：IC01—IC11 已本地实现；全量逐页布局与真实客户端验收尚未完成
> 代码基线：`31d098550750ed1df59dca235b48e8c814b159cb`
> 适用对象：产品、开发、测试；覆盖机器人管理入口及其公共交互页面

当前按钮体验仍存在单列过长、按钮文案承载过多信息、列表操作分散和返回位置不统一的问题。本版按页面类型统一布局：短操作默认两列，配置值移到正文，长对象列表保留可辨认的整行，危险操作和返回分别固定位置。目标是让用户更快找到并准确执行操作，同时保持群、用户、对象和草稿的归属正确。

本版承接[首轮管理按钮改造](./2026-10-15-admin-keyboard-layout.md)，补充逐页设计和验收要求；与首轮规则冲突时，以本版后续实施要求为准。首轮实现和历史验收记录继续保留。初版交付为 PRD 和代码构造点清单。用户追加修复要求后，第十节操作组件已进入本地实现；本轮未部署、未发送 Telegram 测试消息。

## 一 现状与问题依据

首轮已有统一 `admin_keyboard`，短单按钮行可自动合并；管理首页、分类页、命令列表已有显式两列布局。当前代码中有 37 个文件的 79 处调用接入该工具。它按文案宽度和关键词判断，不知道按钮是编辑字段、对象记录、状态切换还是危险动作，因此不能单独承担全量页面设计。

本次静态扫描找到 130 个文件中的 315 个直接构造点：`admin_keyboard` 79 处、`InlineKeyboardMarkup` 235 处、`ReplyKeyboardMarkup` 1 处。完整定位见[按钮构造点清单](./2026-10-15-button-layout-inventory.json)。这是调用点数量，不是页面数，也不是 235 个缺陷；其中包含已正确分列的页面、发布消息、验证题目和公共包装器。调用点清单不等同于所有动态分支已渲染，实施时仍须从入口追到实际页面。

## 二 目标与范围

1. 同层短操作默认两列，每个按钮表达一个明确动作；不靠增加无效按钮凑满一行。
2. 同类页面采用相同的信息顺序和页脚顺序，用户能预判新增、保存、预览、返回的位置。
3. 列表保留完整对象识别能力，设置页减少重复状态和长值；不能为减少行数增加误操作。
4. 对每个页面形成“改造、保留并说明、兼容入口、范围外”结论，不能以接入公共函数代替逐页验收。
5. 改造后按钮仍指向正确群和对象；返回、取消、重复点击、过期按钮、并发编辑不破坏既有业务约束。

范围包括 38 个管理入口、管理首页、群选择、草稿、通用列表、通知、权限、执行恢复、按钮编辑器和通用成员侧导航。既有三项车库业务入口仅登记与复核公共导航外壳，继续沿用原 PRD 的业务范围限制；本版不新增搜索、定位、报告、认证业务能力。自定义发布网格、验证码题目、游戏操作规则和付款流程保持各自契约。

Web 管理后台和文档站属于独立页面体系，不在本次 Telegram 按钮改造实施范围；文档站中的相关流程示意须随实现更新，避免展示旧布局。

## 三 统一布局规范

| 编号 | 规则 | 具体要求 |
|---|---|---|
| BL01 | 页面信息顺序 | 标题 → 当前群及对象 → 必要状态摘要 → 操作提示 → 按钮。完整群 ID、对象 ID 至少在详情/确认页可见；不能只凭截断名称辨认对象 |
| BL02 | 短操作两列 | 配置字段、同级功能入口默认两列，按语义配对，再按使用顺序从左到右、从上到下阅读。奇数末项独占一行 |
| BL03 | 短文案 | 普通操作建议 4—8 个汉字，状态后缀简短；超过 10 个汉字或带长变量时必须审核。字数是提示阈值，最终以真实客户端不截断关键动作和状态为准 |
| BL04 | 信息移出按钮 | 群名、频道名、口令、长时长、统计明细等放正文。按钮用“开群口令”“频道 1”“发送频率”等；单独按钮仍须能识别所属字段 |
| BL05 | 设置开关 | 既有“字段 / 开启 / 关闭”三列语义组可保留，最长字段在手机可读；不能把两个不同字段的状态配成一组。新增字段优先使用短字段名；不借本次布局改造改变即时生效或保存语义 |
| BL06 | 时间和数值 | 15 秒、30 秒、01:00 等短选项允许 3—4 列；正文显示当前值和单位。禁止普通功能菜单照搬四列 |
| BL07 | 动态对象列表 | 默认每个对象一行，按钮包含状态、稳定短 ID、名称摘要。不同对象截断后仍可区分；完整信息在正文/详情。仅短且可唯一辨识的固定选项使用两列 |
| BL08 | 列表工具 | 新增、搜索等同类工具两列；默认每页 8 个对象，超过后分页；按日期/状态筛选沿用已有能力。需要新增搜索能力时另列需求，不把它隐含为排版任务 |
| BL09 | 页脚顺序 | 对象与操作区 → 分页区 → 危险区（如有）→ 导航区。导航为“返回上级 / 刷新”，无刷新时返回整行。编辑器页脚例外见 BL12 |
| BL10 | 危险操作 | 删除、清空、覆盖、重放、发布等产生外部影响的动作须显式标识。删除/清空/覆盖入口独占一行，不与普通编辑或返回混排；确认页用“取消 / 确认删除”等，明确目标和影响 |
| BL11 | 状态表达 | 当前选择用“✓ 已开启”“✓ 精确”等文字与符号共同表达；不可仅凭颜色/表情辨认。未配置不是关闭，处理中不是成功，结果未知不是失败 |
| BL12 | 草稿编辑器 | 正文与封面 → 自定义网格 → 预览与保存 → 清空按钮/放弃修改 → 返回详情。清空与放弃各为明确动作；返回后草稿保留、挂起或丢弃按当前契约说明，不静默改变 |
| BL13 | 空态与不可用 | 空列表显示简短说明和新增入口；无权限/已删除对象显示原因与安全返回。禁止为了占位添加无效操作按钮；页码等状态按钮可只反馈状态，不产生写入 |
| BL14 | 内容长度 | 主设置页常用操作目标不超过 8 行按钮（含导航）；超出时用有名称的二级设置页。常用动作路径最多比原来增加 1 次点击，且不得超过从功能首页 3 次点击；历史深层例外须登记 |
| BL15 | 客户端约束 | 不以空格、零宽字符或无意义长文案撑宽。通过有用的标题、对象和短文案改善显示；机器人消息不提供网页式固定宽度承诺。宽度与换行最终在 Telegram 实机验证 |

单列允许项为：长对象记录、唯一主操作、奇数余项、危险动作入口、单一退出按钮、原有自定义发布行。保留时必须记录理由；“当前就是一列”不是理由。

## 五 典型页面改版示意

以下为目标排布示意，非已上线截图。方括号表示一个按钮，正文中的完整配置值不重复塞进按钮。

**夜间管控首页**

“定时规则”包含启用与起止时间；“开关群口令”包含启用、两个口令及触发口令保留策略。“提示设置”沿用未获准发言等提示语义，与开/关群通知分开。现有直达回调继续兼容。

**广告对象列表**

正文：当前群、筛选条件、总数、页码及记录摘要。对象按钮保留状态与 ID，详情显示完整名称。


## 六 操作逻辑与兼容约束

- 展示层可改变按钮文案、分组和页面组织；同一动作的群 ID、用户 ID、对象 ID、动作参数、URL、权限策略必须保持一致。仅比较按钮完整字典相等不再适用于本版，应比较动作集合与绑定参数，并单独审核文案和布局。
- 新二级页只承接已有动作；新增导航 callback 要注册和测试，旧 callback 不失效。不要在全局消息发送层重排所有键盘。
- 页面分组由语义角色确定，如普通编辑、状态选项、对象记录、提交、危险动作、导航；字符宽度只作辅助。既有 `admin_keyboard` 可作兼容入口，新页面不能只依赖关键词猜测。
- 预览必须保持原只读范围；页面打开、翻页、刷新、返回不触发群发送、积分变更或权限调整。发布、导入、清空、重放等动作继续走原确认和可靠执行路径。
- 编辑完成后返回原群、原对象、原页码及筛选条件；从首页快捷入口和分类入口进入时，返回仍遵循其来源。取消输入后不再把普通消息写进已退出字段。
- 权限在每次写操作前重新校验。群 A 的按钮不能写入群 B，用户甲不能使用用户乙的私有草稿；界面可见不等于有权执行。
- 重复点击、双窗口旧按钮、对象已删除、配置版本冲突必须可解释；保留当前幂等、版本检查和可靠执行机制。界面不得把 `uncertain` 变成普通失败并提供无条件重发。
- 两列状态不能因数字、长群名或语言变化反复跳动；同一页面的结构稳定。动态名称缩略后必须保留区分用的 ID，不用截断后的显示文本作路由参数。

## 十 操作组件与输入续修

用户追加要求修复时间选择、输入、复制和操作组件。本轮授权进入代码修复；此前全量页面目录仍按各项状态推进，不将公共组件修复写成全量改版完成。

| 编号 | 现场代码问题 | 修复与验收要求 |
|---|---|---|
| IC01 | 广告的复制时间包装器只返回“返回”；定时日期页也没有复制按钮 | 接回原生复制；固定 UTC+8 示例使用可复制的代码格式，说明复制后需粘贴发送，不承诺特定按钮颜色 |
| IC02 | 广告示例为带秒格式，原日期解析仅接受分钟 | 示例统一分钟精度；解析兼容已有带秒显示和全角冒号、斜杠日期，拒绝非法日期，不猜测时区和相对日期 |
| IC03 | 90 分钟、1500 分钟等显示丢失余数 | 所有通用间隔文案精确展示天/小时/分钟；实际执行间隔不变 |
| IC04 | 时段结束按钮显示整点，但调度实际包含该小时全部分钟 | 显示 HH:59，明确 UTC+8 与跨天含义；高亮当前值，选开始不保存，选结束才完成 |
| IC05 | 时段第二步只检查存在 start_hour，未绑定当前任务/群 | 校验状态类型、群和任务，旧任务按钮不能使用另一任务的开始值；取消回到详情后输入不再被接收 |
| IC06 | 定时日期输入返回时间范围页不一定退出输入状态 | 明确退出并保留既有草稿语义；返回后普通文本不修改原日期 |
| IC07 | 定时重复间隔只有固定按钮 | 增加自定义分钟输入，验证 1—525600 的整数分钟（保留原快捷选项，扩展原固定值限制），错误留在输入步骤，取消退出；已有快捷值保持 |
| IC08 | 按钮编辑器不提供现有文字/链接/触发文字复制，编辑时看不到原值 | 展示并提供短值原生复制；超过 Telegram 复制字段上限不截断伪装成功，提供当前正文/按钮配置的文件导出 |
| IC09 | 编辑器清空无确认，删除与移动相邻，返回在保存上方 | 管理工具重组；清空草稿增加确认，保存/预览成组，危险操作独立，返回放末尾；发布网格不重排 |
| IC10 | 普通输入校验异常进入通用系统错误提示 | 已知 ValidationError 返回明确格式提示并保留输入；未知异常继续隐藏内部信息 |
| IC11 | 定时编辑进入后提交文本/媒体未重新检查权限及任务归属 | 每次提交重新校验；撤权或任务不属于当前群时退出输入，原配置保持不变 |

原生复制字段限 1—256 字符，依据 [Telegram CopyTextButton](https://core.telegram.org/bots/api#copytextbutton)。不通过截断链接或长文本绕过限制；文件导出仅发送给当前获授权的私聊操作者。日期输入显示业务时区的原始可编辑值，不把客户端本地化时间作为待提交值。

回归必须覆盖示例复制后原样提交、非整小时数、跨天时段、两个任务交替编辑、取消后普通文本、权限撤销、长复制内容和清空确认。运行使用隔离数据库与假的 Telegram 传输，群内消息不在本轮验证范围。

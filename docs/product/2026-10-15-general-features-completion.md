# 2026-10-15 四项通用功能实施与恢复复核

> 需求基线：竞品差距PRD v0.5，CG13、CG12标签及CG02-B。
> 状态：本地候选实现；未提交、未推送、未部署、未运行真实Telegram验收。
> 验证对象：master/feecab8加本会话工作树，Python3.12.9、python-telegram-bot21.6、一次性PostgreSQL16。
> 范围：通用群管理、等级展示和已授权收件人的到期提醒；不扩展其他业务链路。

## 用户可见能力

| 功能 | 入口与行为 | 默认及兼容 |
|---|---|---|
| 开群/关群通知 | 夜间管控分别配置两套封面、纯文本、链接按钮和保留秒数；配置预览只发送给操作人的私聊 | 默认关闭；原删除口令设置只控制触发口令，0秒保留通知 |
| 持久切换计划 | 已有定时器及群消息路径共用数据库计划、唯一身份、按群执行锁；权限、通知及清理分别显示结果 | 时间按Asia/Shanghai；重启只恢复当前应生效边界，过时边界不补发；口令同一消息只处理一次，有效期5分钟 |
| 等级标签 | 积分等级页的全局开关、本级显示开关及独立文案；后台按真实余额匹配升级、降级、停用及无等级状态 | 两级开关默认关闭；不改变媒体权限/身份豁免，不授予管理员；管理员/非在群角色不适用 |
| 广告到期提醒 | 广告详情配置通知人、提前天数、每天时刻、模板；本人私聊同意/撤销；执行记录独立查询 | 默认关闭；建议提前3天起每天10:00，包含到期当天且仅在实际到期前发送；保存ID不代表本人同意 |

标签通过当前SDK的公开`Bot.do_api_request`适配官方`setChatMemberTag`，没有升级SDK或用管理员头衔替代成员标签。官方接口要求普通成员、0—16字且无emoji，机器人须有`can_manage_tags`权限，见[Telegram官方接口](https://core.telegram.org/bots/api#setchatmembertag)。本地采用保守的纯文字/数字/常用标点校验；不支持或缺权限会留下明确失败结果，不能显示已设置。

首次启用完整群权限方案前，读取真实群权限并保存带时间、操作者的快照；读取失败不启用新方案。保存新方案不直接修改群权限，下一次已启用的口令/调度消费它；已有调度开启时，修改当前方案可在下一次巡检应用。

## 持久化与运行契约

新增迁移`0017_generic_admin_delivery`包含：

- `admin_effects`：唯一effect_key、chat_id、kind、配置快照、七态、尝试次数、下次时间、失效时间、租约、远端调用开始标记、结果及错误。
- `level_tag_states`：chat_id/user_id唯一所有权、已确认标签、拟设置标签、对账状态、检查时间、限流恢复时间及错误。
- `notice_consents`：群/广告/收件人授权版本、本人同意开关及时间；不随管理员填写ID自动批准。
- `ad_campaigns.expiry_notice`：独立JSON配置，旧广告默认空对象即关闭。

0017保留审计与所有权，拒绝删除型downgrade。回退必须用理解新计划/状态的兼容版本或前向修复。空库初始化、重复升级及模拟0016旧库升级均已通过Schema Gate；旧广告内容不变、提醒关闭、没有虚构授权。没有生产数据库变更。

调度每60秒巡检。每次最多处理100条副作用；标签每群每批最多100个已记录成员/积分账户，按最早检查时间轮转，新增成员逐批纳入，所有群有巡检机会。标签对账不承诺秒级；429按服务端指定时间暂停标签接口调用，其他标签请求不会继续冲击限流。

权限切换的唯一身份由群、当前边界和权限方案组成；口令由群/消息ID组成。按群使用PostgreSQL执行锁，跨进程互斥；不用进程缓存作为是否执行的唯一依据。权限成功与后续通知计划在同一事务收尾；通知成功与后续删除计划在同一事务收尾。通知失败不撤销已生效权限，权限失败不创建成功通知。

广告提醒身份由广告、到期时刻、收件人、本人同意版本和提醒日期组成。同日重复调度/重启不再发送；配置、到期日或本人同意变化会使旧未发送计划取消。管理员显式取消的计划不由下一轮扫描复活。执行前重新核对广告仍开启、尚未到期、当前收件人及本人授权。旧日期不补发，不能把提醒列表刷新当成发送动作。

## 异常与恢复

| 边界 | 记录及恢复 | 明确不会发生的误报 |
|---|---|---|
| 入队后、远端调用前崩溃 | 未开始的过期租约可重新认领；仍检查配置和时限 | 不把入队算发送成功 |
| 明确429 | 到指定时间后重试，次数上限5；标签保存冷却时间 | 不把限流误记成已送达或永久未知 |
| 权限/参数明确失败 | 永久失败，管理页允许重试明确失败；操作留审计 | 不自动发成功卡片，不改成管理员标签 |
| 发送后网络未知 | uncertain，管理页只读待核实，无直接重发按钮 | 不因刷新/重启重复通知 |
| 远端调用后数据库收尾失败 | 保留已开始的processing，租约过期进入uncertain | 不因没有成功落库就重新发送 |
| 通知清理失败 | 清理记录独立失败；仅引用本系统确认发送的消息ID | 不误删口令、他人消息或把通知发送改成失败 |
| 已有其他来源标签 | conflict，保留原标签；不会用等级标签覆盖 | 不把认证或其他来源标签变成等级身份 |
| 标签设置返回未知 | 后续只读标签；读回匹配目标才确认，否则继续待核实 | 不盲目重复设置/清除 |
| 全局/单级/等级功能关闭、无匹配或降级 | 仅清理或替换自己已确认设置且远端仍匹配的标签 | 不删除外部已改写的标签，不提升管理权限 |
| 已取消/过时/撤权旧按钮 | 重新鉴权、归属与当前状态检查；拒绝跨群执行 | 不套用其他已选群，不复活管理员取消的提醒 |

执行与恢复页每页8条，旧记录可翻页查看；错误和状态用中文说明。未知结果须先核实远端事实，不提供会冒充“核实成功”的本地按钮。原消息未被系统确认时，也不安排删除。

## 自有操作逻辑复核与追加修复

38个稳定功能ID和6类菜单保留。现有入口回归继续走真实Application/Router及PostgreSQL；本轮新配置、同意、取消、返回和编辑输入也从真实注册链检查。没有把38个首页通过解释成全部业务组合已验收。

本轮另外修复：

1. 旧广告规则保存/输入回调缺少重新鉴权，撤权后仍可能进入配置；现在与目标群绑定一起复核。
2. 旧广告输入状态只检查群管理权、不检查广告归属；入口和后续输入都核对所属群，旧跨群状态清理退出。
3. 新广告提醒输入的草稿版本需要绑定广告对象，避免误用群设置版本判断覆盖冲突。
4. 夜间管控页面展示默认开/关群词，但运行时空配置不匹配默认词；默认值已统一。
5. 提醒取消后被周期扫描重新入队、429被当作未知、恢复记录只显示最近10条等新链路问题已修正。
6. 权限原状读回失败、非法字段、非法模板/标签、预览、退出后的普通文本、未知记录重试均有明确处理。

# 管理按钮布局改造与验收

日期：2026-10-15；实施前设计，验收结果随后追加。延续既有 PRD 的导航、输入退出、权限隔离和可靠执行规则。

## 需求与范围

用户反馈许多设置页只有一列，滚动长且不便操作。适用于通用私聊管理菜单、通知、权限、积分、活动配置、导入/克隆及自动化配置页。使用独立的管理键盘工厂；不在全局发送层重新排列键盘，不改变用户编辑保存的发布按钮、底部按钮及实际验证题目。既有车库业务不扩展。

## 布局约定

- 同层短选项默认每行两项，保留原有阅读顺序、文案和完整回调。奇数剩余项单独一行。
- 已有成组的启停/权限三列、数值/时刻选择网格保持语义分组；不把状态标签与对应操作拆散。
- 长文案、动态记录名称、说明标题、删除/覆盖执行等高影响操作保持整行。删除确认与取消继续同一确认组，输入取消保持清晰。
- 返回独立于配置动作；紧邻的刷新和返回组成导航行。分页不与设置混排。
- 内容、URL、回调、群/用户/对象 ID、入口顺序、权限检查与输入生命周期保持原有契约。只对显式接入的管理界面应用，调用方传入的原始行不得被修改。

## 验收标准

| 编号 | 标准 |
|---|---|
| UI01 | 通知四个字段显示为两行两列，预览与执行记录并排；导入/克隆模块短选项两列 |
| UI02 | 同层短菜单紧凑显示；长名称、动态列表与危险操作不强行挤成两列；已有启停/时刻网格不变 |
| UI03 | 每个接入键盘转换前后的按钮顺序、完整字典及回调一一相同；重复渲染幂等，不修改输入对象 |
| UI04 | 真实 Application/Router + 隔离 PostgreSQL 验证布局、群绑定、无权限拒绝、输入取消及返回；伪 HTTP 不产生真实群副作用 |
| UI05 | 静态检查、相关回归和全量回归通过；发布后核验版本和私聊代表页面，记录真实客户端与本地证据边界 |
| UI06 | 未指定成员、第二测试群、所需机器人权限的群测试保持开放；先列对象和操作供确认，不用业务成员代替测试对象 |

## 复核追加：成员权限兼容

核对 Telegram 当前官方 ChatPermissions 文档后，确认旧 SDK 构造器没有 `can_react_to_messages` 和 `can_edit_tag`。原完整方案遗漏这两个配置，直接以构造器重建持久载荷也无法接收新字段。补齐两个独立权限选项，以 SDK 的反序列化能力保留新字段并进入真实请求；旧方案缺省分别沿用文本、置顶权限的官方默认规则。只保存配置，不触发群操作。

验收 UI07：用隔离数据库验证方案保存、完整原权限快照、计划载荷及伪 HTTP 请求包含两个显式权限；旧缺省行为不变，保存无远端写，持久化后重新执行不出现构造器异常。真实群权限切换仍待指定对象和确认。

依据：[Telegram ChatPermissions](https://core.telegram.org/bots/api#chatpermissions)、[setChatPermissions](https://core.telegram.org/bots/api#setchatpermissions)，2026-10-15 核对。

## 实施与证据

已实现：37 个视图文件、79 处管理键盘构建接入统一布局；另补齐成员权限两个新字段和兼容执行。既有按钮构造参数的 AST 对比均一致，新增字段通过既有显式权限键路由产生；没有改群/用户/对象绑定。新增 9 项测试覆盖混合中文/表情、奇数与空行、语义组、幂等、发布按钮不变、通知取消输入、导入/克隆撤权及新权限持久执行。

已验证：相关119项、界面契约149项和新增9项均通过（集合有交集，不相加）；Ruff、质量指标、调用契约、mypy 665文件通过。文档55流程/1404回调精确匹配、0问题。全量回归1283项通过（105.30秒，warning-as-error）；发布/客户端结果待追加。

保留整行的页面类型：群选择与动态记录名称、输入提示单一取消、危险确认及长文案；主页/分类已有两列，数值与时刻选择保留原网格，权限标签/允许/禁止保留三列。用户编辑的按钮网格、预览和发布键盘继续使用原布局。

生产发布前只读检查：7条 ChatSettings 哈希和专用群数据已冻结；当前没有启用或保存完整方案的群锁配置，避免存量计划因增加权限字段而重新生成。未读取或输出密钥。
